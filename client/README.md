# MARCH ROLE PLAY — клиентские файлы

Лаунчер копирует **уже установленную пользователем GTA San Andreas** в выбранную отдельную папку `GTA San Andreas/`, не меняя оригинал. GTA SA и MTA не входят в наш дистрибутив.

После полной установки режим «Обновить файлы» получает `client/manifest.json` с основной ветки репозитория и скачивает **только** указанные там файлы внутрь `MARCH Assets/`. Пока список `files` пустой — моделей для скачивания ещё нет.

## Добавление модели

Загрузить свои DFF/TXD/COL/IMG на HTTPS-хостинг проекта, посчитать SHA-256 и размер, затем добавить в `client/manifest.json` запись:

```json
{
  "path": "MARCH Assets/vehicles/example.dff",
  "url": "https://your-project-cdn.example/vehicles/example.dff",
  "sha256": "64 шестнадцатеричных символа настоящего SHA-256 файла",
  "size": 12345
}
```

`path` должен находиться внутри `MARCH Assets/`. SHA-256 и `size` обязательны; не используйте фиктивные значения. При несовпадении файл не устанавливается. Обновления используют временный файл и атомарную замену; пользователь может отменить операцию.

## Ограничения текущего этапа

- Вход через `march_auth` и запуск `mtasa://127.0.0.1:22003` сохранены без изменений.
- Установщик **пока не скачивает и не настраивает MTA автоматически**; необходим официально установленный MTA 1.6.
- Простое помещение моделей в `MARCH Assets/` само по себе не подключает их к MTA. Для применения DFF/TXD/COL и IMG нужен клиентский MTA-ресурс со связкой на нужные model IDs, коллизии и серверной синхронизацией, либо отдельная согласованная схема предустановки в MTA cache. Не редактируйте `models/gta3.img` GTA:SA без особой необходимости.
- Это первый рабочий этап установщика, **не полностью автономный GTA/MTA клиент**. Перед публичным выпуском проверить сборку на Windows и интеграцию с установленным MTA.



## Единая папка MARCH ROLE PLAY

```text
MARCH ROLE PLAY/
├── GTA San Andreas/        # отдельная копия оригинальной GTA SA
│   ├── gta_sa.exe
│   ├── models/gta3.img
│   └── data/
├── MTA San Andreas/        # официальный MTA 1.6, устанавливается отдельно
│   ├── Multi Theft Auto.exe
│   ├── MTA/
│   └── mods/
└── MARCH Assets/           # обновляемые файлы моделей и текстур
```

1. «Полная установка» — выбрать установленную пользователем GTA SA и корневую папку `MARCH ROLE PLAY`. Лаунчер копирует GTA и создаёт папки для MTA и моделей.
2. Нажать «СКАЧАТЬ MTA» — открыть официальный сайт MTA и запустить его установщик. **Путь установки MTA**: `MARCH ROLE PLAY/MTA San Andreas`. **Путь GTA SA**, запрашиваемый тем же установщиком: `MARCH ROLE PLAY/GTA San Andreas`. Кнопка «КОПИРОВАТЬ ПУТИ» показывает их в одном месте.
3. После установки нажать «ИГРАТЬ». Если отдельная GTA найдена, лаунчер **требует локальный MTA** и запускает `MTA San Andreas/Multi Theft Auto.exe` с адресом сервера. До настройки отдельной GTA сохранён прежний запуск через `mtasa://`.
4. «Обновить файлы» сверяет манифест `MARCH Assets/` по SHA-256. Он не меняет стандартные GTA/MTA файлы.

**Важно:** физически файлы GTA SA и MTA должны оставаться в **разных подкаталогах**. В MTA общесистемная настройка пути GTA через установщик/реестр, так что размещение рядом недостаточно: надо указать именно копию из сборки MARCH при установке MTA. При наличии явного несовпадения лаунчер покажет предупреждение вместо запуска не той копии.

**Замена моделей:** `gta3.img` можно редактировать в изолированной GTA, но MTA может блокировать изменённые IMG античитом; стабильный план — заранее устанавливать большие пакеты DFF/TXD/COL/IMG с лаунчером, а привязку делать клиентским MTA загрузчиком (MTA 1.6 поддерживает `engineLoadIMG`). Модели пока не добавлены. Дистрибутив не содержит файлов GTA SA или MTA и не запускает установщик MTA автоматически. Windows Smart App Control может блокировать наш неподписанный лаунчер — нужна доверенная подпись издателя, не отключение защиты.

## Автоматическая проверка и восстановление файлов (0.2.0)

Лаунчер обращается по **HTTPS** к опубликованному [манифесту проекта](https://github.com/VladZeleznij/Vlados1k1/blob/main/client/manifest.json). Это текущий сервер обновлений проекта (GitHub), а **не MTA UDP-сервер**. Когда появится свой файловый/CDN-сервер, можно перенести `client/manifest.json` и файлы на него, изменив адрес в `ProjectUpdateService.cs`.

- Проверка стартует автоматически при открытии лаунчера, если задана папка игры. Проверка повторяется перед **Играть**, **Войти** и **Зарегистрироваться**, а также по кнопке **ПРОВЕРИТЬ** и во вкладке «Обновить файлы».
- SHA-256 вычисляется для каждого файла из `files`. При отсутствии файла, неверном размере или хеше загружается **только этот файл** по HTTPS и проверяется по SHA-256 перед заменой. Показывается прогресс, версия, количество восстановленных файлов.
- При удалении `MARCH Assets/client-pack.json` лаунчер должен восстановить его из серверного манифеста версии 0.2.0. Этот файл — **тестовый маркер пакета**, ещё не автомобиль и не карта. Чтобы обновлялись реальные DFF/TXD/COL/IMG, их нужно добавить в манифест с реальными размером, хешем и HTTPS URL.
- Не обновляем исполняемые файлы, пароль, GTA или MTA через удалённый манифест. Если отсутствуют основные файлы GTA, лаунчер может восстановить их из указанной пользователем локальной копии. При отсутствии самого MTA показывает подсказку по официальной установке.
- Нет тихого удаления пользовательских файлов, а доступные имена файлов ограничены каталогом `MARCH Assets/` и расширениями игровых ресурсов. Прерывание загрузки не портит уже работающие версии файлов.
- При недоступном сервере обновлений отображается ошибка; перед запуском сборки с настроенной папкой лаунчер требует успешной проверки. На полностью старой конфигурации без выбранной папки проекта сохраняется прежний способ запуска.

Тест: установи обновлённый лаунчер, выбери папку с GTA и MTA, нажми «ПРОВЕРИТЬ». После появления `MARCH Assets/client-pack.json` удали **только этот файл** и нажми «ПРОВЕРИТЬ» снова: он должен быть скачан заново. Не удаляй оригинальную GTA/MTA для тестирования.
